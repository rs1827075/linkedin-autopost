## Post text (edit freely, this is what gets published)

Building custom user interfaces on Salesforce often meant limiting your stack to Lightning Web Components, even when your team had deep React experience. Juggling separate frameworks used to slow down delivery for complex enterprise features.

Salesforce Multi-Framework is now generally available, allowing developers to run React applications natively right inside Salesforce. You can build with React without managing complex auth or token overhead, while keeping standard access to GraphQL data operations and Apex calls.

Picture a case where your front-end team builds a custom wealth dashboard using React components, deploying it directly into your Salesforce environment. They can query financial account records using GraphQL and trigger backend Apex logic seamlessly without wrestling with separate infrastructure.

For Financial Services Cloud architectures, this opens up interesting paths for teams migrating existing web applications into client-facing portals or advisor workspaces. It bridges the gap between specialized UI needs and core CRM data integrity.

How is your team handling UI framework choices on Salesforce right now?
